## 1. Reverse Letters in Pairs

### Problem

Given a string `s` consisting of lowercase English letters, reverse its letters in adjacent pairs:

- Swap the 1st and 2nd characters.
- Swap the 3rd and 4th characters.
- Continue in the same way for the rest of the string.
- If the string has an odd number of characters, leave the final character unchanged.

### Examples

```text
s = "abcdef"
output = "badcfe"
```

```text
s = "abcde"
output = "badce"
```

### Standard Answer

```python
def solution(s):
    chars = list(s)

    for i in range(0, len(chars) - 1, 2):
        chars[i], chars[i + 1] = chars[i + 1], chars[i]

    return "".join(chars)
```

### Explanation

Python strings cannot be modified directly, so first convert `s` into a list. The loop starts at index `0` and advances by `2`, swapping each adjacent pair. Using `len(chars) - 1` prevents an unpaired final character from being accessed.

### Complexity

- Time: `O(n)`
- Space: `O(n)`

## 2. Debugger Actions

### Problem

You are debugging a code snippet whose final line number is `codeLength`. The sorted list `breakpoints` contains unique breakpoint line numbers. The debugger initially starts on line `1`.

Process every string in `actions`:

- `"next"`: move forward exactly one line.
- `"continue"`: move forward to the first breakpoint strictly after the current line.

Return the line on which the debugger finishes.

The input guarantees that every action is valid.

### Example

```python
codeLength = 55
breakpoints = [2, 5, 21, 44]
actions = ["next", "next", "continue", "next", "next"]
```

Movement:

```text
1 → 2 → 3 → 5 → 6 → 7
```

Output:

```text
7
```

### Standard Answer

```python
def solution(codeLength, breakpoints, actions):
    current_line = 1
    breakpoint_index = 0

    for action in actions:
        if action == "next":
            current_line += 1

        else:  # action == "continue"
            while breakpoints[breakpoint_index] <= current_line:
                breakpoint_index += 1

            current_line = breakpoints[breakpoint_index]

    return current_line
```

### Explanation

Because the breakpoints are sorted and the debugger only moves forward, `breakpoint_index` also moves forward. For `"continue"`, skip every breakpoint at or before the current line, then move to the next one.

`codeLength` does not need to be used directly because the problem guarantees that the provided actions are valid.

### Complexity

Let `a` be the number of actions and `b` the number of breakpoints.

- Time: `O(a + b)`
- Extra space: `O(1)`

## 3. Robot and Lasers on a Board

### Problem

There is a `numRows × numColumns` board. Each laser is located at `[row, column]` and destroys every cell in its entire row and entire column.

A robot initially stands at `(curRow, curColumn)`. Its initial cell is protected, even if a laser covers that cell. The robot chooses one of four directions—up, down, left, or right—and then moves only in a straight line without turning.

Return the maximum number of safe cells the robot can move through before reaching a laser-covered cell or leaving the board.

Coordinates are **1-based**:

```text
1 ≤ row ≤ numRows
1 ≤ column ≤ numColumns
```

### Example

```python
numRows = 8
numColumns = 8
curRow = 5
curColumn = 3
laserCoordinates = [[1, 6], [2, 8]]
```

The dangerous rows are `{1, 2}`, and the dangerous columns are `{6, 8}`.

| Direction | Safe cells | Count |
|---|---|---:|
| Up | `(4,3), (3,3)` | 2 |
| Down | `(6,3), (7,3), (8,3)` | 3 |
| Left | `(5,2), (5,1)` | 2 |
| Right | `(5,4), (5,5)` | 2 |

Output:

```text
3
```

### Standard Answer

```python
def solution(numRows, numColumns, curRow, curColumn, laserCoordinates):
    dangerous_rows = set()
    dangerous_columns = set()

    for laser_row, laser_column in laserCoordinates:
        dangerous_rows.add(laser_row)
        dangerous_columns.add(laser_column)

    directions = [
        (-1, 0),  # up
        (1, 0),   # down
        (0, -1),  # left
        (0, 1)    # right
    ]

    max_safe_cells = 0

    for row_change, column_change in directions:
        # Start with the first cell after the protected initial cell.
        row = curRow + row_change
        column = curColumn + column_change
        safe_cells = 0

        while 1 <= row <= numRows and 1 <= column <= numColumns:
            if row in dangerous_rows or column in dangerous_columns:
                break

            safe_cells += 1
            row += row_change
            column += column_change

        max_safe_cells = max(max_safe_cells, safe_cells)

    return max_safe_cells
```

### Explanation

A cell is dangerous if its row **or** its column contains a laser:

```python
row in dangerous_rows or column in dangerous_columns
```

The scan begins one step away from the robot because the initial cell is protected and is not counted. The lower boundary is `1`, not `0`, because the problem uses 1-based coordinates.

This is a four-direction simulation, not BFS or DFS: after choosing a direction, the robot continues along one straight line and never branches.

### Complexity

Let `L` be the number of lasers.

- Time: `O(L + numRows + numColumns)`
- Space: `O(L)`

## 4. Blocks and Obstacles on an Infinite Number Line

### Problem

An infinite integer number line supports two kinds of operations:

- `[1, x]`: place an obstacle at coordinate `x`. It is guaranteed that no obstacle is already located there.
- `[2, x, size]`: determine whether a block of length `size` can occupy the integer coordinates immediately before `x`.

For a query `[2, x, size]`, the checked interval is:

```text
[x - size, x - 1]
```

Append `"1"` if the interval contains no obstacle; otherwise append `"0"`. Query operations only check availability and do not actually add a block.

Return the results of all type-2 operations as one binary string.

### Example

```python
operations = [
    [1, 2],
    [1, 5],
    [2, 5, 2],
    [2, 6, 3],
    [2, 2, 1],
    [2, 3, 2]
]
```

| Query | Checked interval | Result |
|---|---|---|
| `[2,5,2]` | `[3,4]` contains no obstacle | `1` |
| `[2,6,3]` | `[3,5]` contains obstacle `5` | `0` |
| `[2,2,1]` | `[1,1]` contains no obstacle | `1` |
| `[2,3,2]` | `[1,2]` contains obstacle `2` | `0` |

Output:

```text
"1010"
```

### Standard Answer

```python
from bisect import bisect_left, bisect_right


def solution(operations):
    # Collect every coordinate that may later contain an obstacle.
    positions = []

    for operation in operations:
        if operation[0] == 1:
            positions.append(operation[1])

    positions.sort()

    # Fenwick tree: records which obstacle positions have been activated.
    tree = [0] * (len(positions) + 1)

    def add(index):
        while index < len(tree):
            tree[index] += 1
            index += index & -index

    def get_sum(index):
        total = 0

        while index > 0:
            total += tree[index]
            index -= index & -index

        return total

    result = []

    for operation in operations:
        if operation[0] == 1:
            x = operation[1]

            # Fenwick-tree indexes start at 1.
            index = bisect_left(positions, x) + 1
            add(index)

        else:
            x = operation[1]
            size = operation[2]

            left = x - size
            right = x - 1

            left_index = bisect_left(positions, left)
            right_index = bisect_right(positions, right)

            obstacle_count = (
                get_sum(right_index) - get_sum(left_index)
            )

            if obstacle_count == 0:
                result.append("1")
            else:
                result.append("0")

    return "".join(result)
```

### Explanation

Coordinates may be as large as `10^9` or as small as `-10^9`, so it is impossible to build an array covering the entire number line. Instead:

1. Collect and sort only the coordinates that may contain obstacles. This is coordinate compression.
2. Use a Fenwick tree to record which of those obstacles have already been added.
3. For each query, use binary search to locate the compressed range corresponding to `[x-size, x-1]`.
4. Ask the Fenwick tree how many active obstacles are inside that range.

The boundary searches are intentionally different:

```python
left_index = bisect_left(positions, left)
right_index = bisect_right(positions, right)
```

`bisect_right` includes an obstacle located exactly at the right boundary. Using `bisect_left` for both boundaries would incorrectly miss it.

A simpler solution that loops through every obstacle for every query is logically correct but can require `O(n²)` time and exceed the execution-time limit.

### Complexity

Let `n` be the number of operations.

- Time: `O(n log n)`
- Space: `O(n)`
